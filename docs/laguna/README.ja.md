# Abyss で Laguna-S-2.1 を動かす

[Laguna-S-2.1](https://huggingface.co/unsloth/Laguna-S-2.1-GGUF)（poolside。llama.cpp の `laguna`）は、パラメータ
118B、1 トークンあたり約 8B が動く MoE モデルです。エンジンは Qwen3.5-MoE の層パスの上に、専用のアテンションを載せて
動かします。

- **アテンション層 48 枚**：4 枚に 1 枚（12 枚）がフルアテンション、残り 36 枚は **512 トークンのスライディング
  ウィンドウ**。KV ヘッドは 128 次元が 8 本、クエリヘッドはフル層 48 本・ウィンドウ層 72 本。q / k に RMS ノルム、
  NEOX RoPE（フル層：先頭 64 次元、base 5e5、元コンテキスト 8K からの **YaRN** x32／ウィンドウ層：128 次元すべて、
  base 1e4）、専用の射影から出るヘッドごとの **softplus 出力ゲート**。
- 0 層目は密な SwiGLU FFN、1-47 層は **256 エキスパート中 10 本**（sigmoid スコア＋選択バイアス、重みは正規化して
  x2.5）と、ゲートなしの**共有エキスパート**。エキスパートプール・RAM ティア・CPU レーンは他のモデルと同じ仕組みで
  動きます。NextN ブロックはありません。
- ウィンドウ層はコンテキスト全体ではなく 2,560 行のリング（ウィンドウ＋プロンプト 1 区切り分）だけを持つので、
  KV キャッシュは 8K で約 0.7 GB、長くなっても増えるのはフル層 12 枚の分（1 位置 24 KB）だけです。

## GGUF とパック

計測したのは unsloth の `UD-IQ4_XS`（3 分割、58 GB。エキスパートは IQ3_S / IQ4_XS と一部 Q6_K、密な部分は Q8_0）です。

```sh
./setup-deepseek.sh --model laguna --download-model
```

で、ダウンロード・エンジンのビルド・パック作成・`abyss-laguna-iq4_xs.json` の書き出し（RAM ティアはその PC の RAM
に合わせた値、サンプリングはモデルカードの temperature 1.0 / top_k 20）まで済みます。手で作る場合：

```sh
.venv/bin/python tools/iq_pack.py \
  --gguf <models>/unsloth/Laguna-S-2.1-GGUF/UD-IQ4_XS/Laguna-S-2.1-UD-IQ4_XS-00001-of-00003.gguf \
  --out <models>/unsloth/Laguna-S-2.1-GGUF/UD-IQ4_XS/pack
```

チャットテンプレートは既定で思考します（`<assistant><think>`）。`"chat_template_kwargs": {"enable_thinking": false}`
で思考を切れます。サーバーは `</assistant>` で止まります。

## 速度と品質（RTX 5090 を上限つきで使用、iGPU なし、RAM ティア 50 GB）

4,058 トークンのプロンプトに続けて 512 トークンを greedy で生成、コンテキスト 32K、毎回新しいプロセスで 3 回測った
中央値です。比較の llama.cpp は同じ PC・同じ上限で測りました。

| VRAM | 生成 | プロンプト | llama.cpp 生成 / プロンプト |
| --- | ---: | ---: | ---: |
| 16 GB | 42.5 tok/s | 859 tok/s | 32.0 / 318 |
| 24 GB | 50.9 tok/s | 1,005 tok/s | 38.1 / 391 |
| 32 GB | 60.6 tok/s | 1,174 tok/s | 43.2 / 470 |

（v1.3.142 の値。n-gram の下書きと、速くなった生成時の attention によります。v1.3.140 は生成 36.3 / 41.4 / 47.4 tok/s、
プロンプト 842 / 975 / 1,144 でした。下書きはコードの書き換えのような編集タスクで効き（24 GB で 400 トークンの書き換えが
+5-14%）、普通の文章ではほとんど効きません。検証ウィンドウは VRAM を約 0.4 GB 使います。出力は v1.3.141 とビット単位で
同じです。）

エキスパートはすべて VRAM か RAM ティアに載り、SSD からは読みません。生成の待ち時間は CPU レーン（RAM ティアの
エキスパートを CPU で計算する分、1 トークン 10-17 ms）が占めています。

llama.cpp（CUDA）との KL は、英語・日本語・コード計 3,071 トークンで 0.024（最上位トークン一致 93.4%）、プロンプト
パスで 0.019、長文の 8,192-10,239 番目（YaRN の元コンテキストより後）で 0.014 でした。同じトークンで llama.cpp 自身
の CPU 版と CUDA 版を比べても 0.024 の差が出ます。256 本から 10 本を選ぶルーターは僅差の候補が多いためで、両エンジン
ともその下限にいます。
